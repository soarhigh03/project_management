# PATZ Team Dashboard

PATZ · room42 · mandudang 팀의 일정, RnR, 공용 예산, 계정, 회의록을 관리합니다. 현재 PATZ 로그인으로 세 프로젝트의 팀 대시보드에 접속합니다. jarvis·말미잘(mijal)은 프로젝트 등록에서 제거했습니다. 기존 DB 기록은 보관하며, 해당 프로젝트의 로그인과 API 접근은 차단됩니다.

## 실행

Node.js 20 이상이 필요합니다.

```sh
npm ci
npm run dev
# http://localhost:3000
```

기존 `config/projects.js`의 프로젝트 비밀번호를 사용합니다. 저장소에 기본 데모 비밀번호나 새 로그인 우회 경로는 추가하지 않았습니다.

```sh
npm run build   # 회의록 편집기 번들 생성
npm test        # 임시 저장소를 사용하는 API·데이터·동시 편집 통합 테스트
```

## 화면과 데이터

- 새 대시보드: `/p/patz/dashboard`
- 이전 UI: `/legacy/p/patz/bugs` (기능·회의록 탭 포함). 원본 화면과 수정 중이던 CSS/JS를 `public/legacy/`에 보관했습니다.
- 이전 프로젝트 선택 화면: `/legacy/index.html`
- 이전 회의록: PATZ 회의록을 새 대시보드에 최초 한 번 복사합니다. 원본 회의록과 버그·기능 데이터는 변경하지 않습니다. 복사 이후 두 회의록의 편집 내용은 독립적입니다.

우측 프로젝트 메뉴는 일정과 RnR의 범위를 바꿉니다. `all`은 세 프로젝트 전체입니다. RnR 프로젝트 칩에서 다른 프로젝트를 고르면 전체 보기로 전환하고 RnR에 해당 필터를 적용합니다. 예산·계정·회의록은 모든 프로젝트에서 같은 데이터를 봅니다.

일정은 날짜순으로 표시하고, RnR·지출·계정·회의록은 새로 추가한 항목이 맨 위에 표시됩니다. RnR은 기존 드래그 순서를 유지하면서 새 항목을 그 위에 추가합니다. 직접 추가한 섹션은 맨 위로 스크롤됩니다.

데스크톱은 화면 전체가 고정되고 각 섹션의 목록만 스크롤됩니다. 예산의 Remaining Balance는 항상 하단에 표시됩니다. 760px 이하에서는 섹션을 세로로 쌓습니다.

## 입력과 편집

- 일정: 제목, 날짜, 프로젝트, 중요 여부. 목록에는 일·요일을 표시하고, 전체 보기에서는 프로젝트를 일정 뒤 위첨자로 표시합니다. 중요 일정은 `#d11010`으로 표시합니다.
- 예산: 항목, 수량, 결제일, 단가. `2,000,000 − Σ(수량 × 단가)`로 잔액을 계산합니다.
- RnR: 마감일, 항목, 프로젝트, 담당자, 상태, 세부 할 일. 담당자는 은우·민우·채은·undefined, 상태는 not finished·finished입니다.
- RnR 필터: 기본 상태는 전체이며 완료된 줄은 회색으로 표시합니다. 필터 칩은 가장 긴 옵션에 맞춰 폭을 유지하고, 같은 스타일의 목록이 칩 아래로 펼쳐집니다. 방향키·Enter·Escape로도 선택할 수 있습니다.
- RnR 수정: 셀 더블클릭 또는 셀에 초점을 둔 뒤 Enter/F2. 점 세 개를 드래그하면 순서가 저장됩니다. 핸들에서 Alt+위/아래도 지원합니다. 세부 할 일도 같은 작업 내에서 재정렬할 수 있습니다.
- 계정: 서비스, 아이디, 비밀번호, 메모. 카드: 카드 이름, 번호, 명의자, 유효기간, CVC(메모 필드). 카드 번호는 목록에 전체 표시합니다. 계정 비밀번호와 카드 유효기간·CVC는 가리고, 눈 아이콘을 누르면 표시하며 옆 복사 버튼으로 복사합니다. 표시한 값은 15초 뒤 또는 창이 비활성화되면 가려집니다.
- 회의록: 추가한 순서의 내림차순. 클릭하면 전용 편집기로 이동하고 제목을 더블클릭하면 목록에서 이름을 수정합니다.
- 편집기: `#`/`##` 제목, 글머리/번호/체크 목록, 인용, 코드, 링크, 굵게/기울임, 이미지 파일·드롭·클립보드 붙여넣기. 편집 중 자동 저장됩니다.

회의록은 Tiptap + Yjs 변경 병합을 사용합니다. 활성 편집 화면은 1초마다 동기화하고 타이핑 후 250ms에 변경을 전송합니다. 여러 사람이 같은 문서를 수정해도 문서 전체를 덮어쓰지 않습니다. 재전송은 중복 적용되지 않으며, 통신 실패 시 브라우저 IndexedDB에 초안을 보관합니다. 일반 목록은 3초 간격으로 갱신합니다. 한 항목의 메타데이터를 동시에 수정하면 버전 충돌을 안내합니다.

## 저장소와 배포

기존 Vercel + Upstash Redis 구성을 사용합니다. 로컬 개발에서는 `data/kv.json`에 저장합니다. `TT_DATA_FILE`을 지정하면 테스트용 파일로 분리할 수 있습니다.

| 환경 변수 | 용도 |
| --- | --- |
| `AUTH_SECRET` | 기존 로그인 세션 서명. 배포 시 필수, 16자 이상 |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | Upstash REST 저장소 (`UPSTASH_REDIS_REST_URL/TOKEN`도 지원) |
| `VAULT_SECRET` | 선택: 계정 암호화 전용 키. 없으면 `AUTH_SECRET`을 사용 |

비밀번호와 카드 상세는 AES-256-GCM으로 암호화합니다. 사용 중인 암호화 키를 변경하면 기존 값을 복호화할 수 없으므로 키를 안전하게 유지해야 합니다. 일반 목록 응답에는 카드 번호 전체를 포함하지만 암호문, 비밀번호, 유효기간, CVC는 포함하지 않습니다. CVC는 카드 메모 필드에 입력하며 다른 카드 상세와 함께 암호화해 저장합니다.

새 API는 PATZ 세션을 검사하고 변경 요청의 Origin을 확인합니다. Redis에서는 Lua 비교·교환으로 항목의 동시 수정을 보호합니다. 회의록 업데이트는 불변 변경 단위로 저장하고 주기적으로 합칩니다. 삭제 항목은 tombstone으로 남기므로 관리자가 복원할 수 있습니다. 기존 UI의 API는 기존 동작을 유지합니다.

현재 변경은 로컬 저장소에 구현되어 있습니다. 배포는 기존 Vercel 프로젝트의 정상 배포 절차를 사용합니다. `public/js/note-editor.bundle.js`는 빌드 산출물이며 `src/note-editor.js`를 수정한 뒤 재생성합니다.
